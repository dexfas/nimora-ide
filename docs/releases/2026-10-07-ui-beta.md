# Nimora Beta — Windows x64 UI Release (2026-10-07)

本次同步此前的 Mission 自治、同 Project 后续工作、API Worker 与资源策略，以及完成的 Product Shell 和 R19 恢复/审核修复。保留已有权限、Human 确认与执行结果不明时禁止重播的边界。

## 下载与首次使用

从 [GitHub Release](https://github.com/dexfas/nimora-ide/releases/tag/nimora-beta-20261007-ui) 下载 `Nimora-Beta-Windows-x64-20261007-UI-Release.zip`，完整解压后双击 `Start-Nimora.cmd`。不需要源码、Node.js 或 npm，包内 Gateway 使用发行程序自带运行时。

1. 打开单个项目文件夹，并在原生工作区信任页面确认。
2. 在“AI 资源”选择网页或 API。网页需登录并主动共享页面；API 需配置端点、模型、协议和密钥，密钥仅在产品密码框输入。
3. 新建项目目标，按产品提示确认启动与工具权限；结果收敛后审核并确认正式完成。

本机网页/API 通道无需 Cloudflare；外部 AI 通过公网 MCP 连接本机是另一个部署场景。随包中文 `README-Nimora.txt` 有完整引导。

## UI 修正

- 长操作等待状态跟随宿主真实结果，重复执行不排队；失败原因保留在页面。
- 引导首次工作区、网页/API 配置及后续资源偏好，权限状态按任务显示。
- 区分等待启动、实际运行、待审核、待核实与正式完成，修正归档任务进度计数。
- 定时刷新保留滚动位置、展开详情和输入焦点；支持窄窗口与深浅主题。

## 验证与使用范围

第一方 typecheck/compile、39 项集成回归、48 个 Edge 界面检查通过。完整 desktop bundle/语法检查、官方 Extension 更新与 packaging、全新用户目录的实际 Webview、目录与 ZIP 完整回解后的独立启动验证通过。Core strict typecheck 使用已记录的恢复树兼容开关，不宣称完整 Core strict typecheck 通过。

本轮没有重新调用真实模型或代点原生授权。DeepSeek 网页两轮项目与 API 正式完成的历史验收继续保留，不能将其当作这个新包所有账号/Provider/混合并行场景的重新验收。完整说明见 [UI 与发行收尾记录](https://github.com/dexfas/nimora-ide/blob/main/docs/architecture/UI_RELEASE_CLOSEOUT_2026-10-07.md)。

这是有人监督的 Beta，Stable OS sandbox 认证仍未通过。API 单 Worker 模型调用次数硬上限与严格金额预算尚未实现；外层最多 8 轮自治并不等于模型调用次数上限。
